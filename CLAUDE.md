# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static browser music player (plain HTML/CSS/ES modules, no build step, no framework, no linter) deployed via GitHub Pages from `main` / root, so a push to `main` is a production deploy (live at `https://arafat-bin-reza.github.io/Mixtape/`). `package.json` exists only for the track-list generator and tests; the app itself has no runtime dependencies. `node_modules/` and `test-results/` are in `.gitignore`, but ~570 `node_modules` files and `test-results/.last-run.json` are still tracked in the index. Running tests modifies the tracked files, so leave them out of commits unless asked, and don't "clean them up" as a side effect of unrelated work.

## Commands

```bash
npm install                              # devDeps only: @playwright/test, music-metadata
npm run serve                            # node scripts/serve.mjs 8000 (static server with HTTP range support)
npm run generate                         # regenerate data/tracks.json from assets/audio/ (+ extract covers)
npx playwright install chromium          # once, before first browser test run
npm test                                 # unit tests then Playwright
npm run test:unit                        # node --test tests/unit/*.test.js (no browser)
npm run test:e2e                         # Playwright only; starts scripts/serve.mjs itself (reuseExistingServer)
(cd collector && npm install && npx wrangler dev --port 8787 --var ADMIN_TOKEN:localtest)   # audit collector locally; run `npm run schema:local` there once first
(cd resolver && npm start)               # optional YouTube audio resolver on 127.0.0.1:8790; needs yt-dlp on PATH
(cd collector && npm run deploy)         # wrangler deploy to the live Worker; `npm run schema:remote` applies schema.sql to the live D1
node --test --test-name-pattern "Vimeo" tests/unit/url-parse.test.js   # single unit test by title (flag must come before the file)
npx playwright test tests/links.spec.js -g "YouTube"   # single browser test by title
PORT=8010 npx playwright test                           # when port 8000 is taken (another dev API server often holds it on this machine)
```

These are POSIX-shell forms and the dev machine is Windows: in PowerShell use `$env:PORT = 8010; npx playwright test` and `cd collector; npm install; ...` instead of the env prefix and the `( … )` subshell.

Playwright has `reuseExistingServer: true`, so if something unrelated is already listening on the chosen port every test fails with missing elements. Check `curl localhost:8000` before suspecting the app.

`npm run test:unit` passes a quoted glob to `node --test`, which Node expands itself; that needs Node 21 or later (the dev machine has 24), so on Node 20 list the files explicitly.

The app must be served over HTTP (ES modules + `fetch`); opening `index.html` from disk will not work. There is no Python on the dev machine; the Node server replaces `python3 -m http.server`. CI uses Node 20, and the only workflow is the track-list generator: nothing runs the tests on push, so run `npm test` locally before pushing to `main`.

## Architecture

Everything flows through a single mutable state object with a pub/sub `setState` (`js/state.js`). Modules never call each other to update the UI; they patch state and subscribers react. `setState` is a bare `Object.assign` that calls every subscriber synchronously on every patch (dozens of times a second during playback), with no equality check or batching, so each subscriber does its own change detection and they do it by reference: `ui.js` compares `[tracks, position, order, failed]` and `audit.js` compares `tracks` and `failed` by identity. Always replace state arrays (`failed: [...failed, id]`), never mutate them in place, or the list will not re-render and the audit log will miss the event. `state.error` is the toast channel: `ui.js` shows it whenever the string differs from the last one it saw, so setting the same message twice in a row shows nothing the second time (non-state code can call `toast()` exported from `ui.js`, as `app.js` does).

- `js/app.js` — entry point (top-level `await`). Loads `config.json`, restores persisted settings, wires `player`, `ui`, and `media-session`, then loads four track sources in parallel: repo (`data/tracks.json`), Cloudinary shared list, local IndexedDB files, and URL tracks. Playlist order is repo → shared (minus the user's own uploads) → personal (local files + URL tracks merged and sorted by `added`). Persists `{volume, muted, shuffle, repeat, last}` to `localStorage` key `music-player:settings` on every change.
- `js/playlist.js` — owns `tracks`, `order` (array of indices into `tracks`; reshuffled when shuffle toggles or a shuffled loop wraps), and `position` (index into `order`). `current()` = `tracks[order[position]]`. `next()` skips ids in `state.failed`.
- `js/player.js` — facade over pluggable **engines** in `js/engines/`. Picks an engine by `track.provider` (`youtube` / `soundcloud` / `vimeo` / `spotify`, anything else → `html-audio`), destroys the old one on provider change, and mirrors engine events into state (including the optional `onPreview` handler, which sets `state.preview` for Spotify's 30 s logged-out previews). Public API (`init/play/pause/toggle/seek/seekBy/setVolume/toggleMute`) is what `ui.js` and `media-session.js` use. There is no "load track" call: `player` subscribes to state, and when `tracks[order[position]]` changes id it loads the new track with `autoplay: state.playing`, so `playing` is both intent (set by `playlist.select`) and status (set by engine events). Each engine's handlers are guarded by `engine === eng`, so late events from a replaced engine are dropped. The `html-audio` engine is created once and reused (`unload()` rather than `destroy()`); embed engines are rebuilt on every provider change.
- `js/engines/*.js` — one object per provider implementing `load/play/pause/seek/setVolume/setMuted/currentTime/duration/destroy` and reporting through `handlers.{onTime,onDuration,onPlay,onPause,onEnded,onError,onBlocked}` (plus the optional Spotify-only `onPreview` / `onItem` and YouTube-only `onAd` / `onReveal`). The interface contract is written out in the header comment of `js/engines/html-audio.js`. Provider SDKs load lazily via `engines/sdk.js` the first time they are needed. The YouTube and Spotify players render in `#embed` inside `.cover`, shown via `data-embed="youtube"` / `data-embed="spotify"`; provider terms require them to stay visible, and Spotify always does. For YouTube the owner chose to depart from that: `config.json` `playback: { hideVideo, muteAds }` (both currently `true`, both off when absent, so tests that stub `config.json` to `{}` get the visible player) is passed to `player.init` and `initUI`, and reaches engine factories as `options`. `hideVideo` keeps the iframe full-size but `ui.js` sets `data-audio-only` on `#cover` so the artwork covers it; if a play request has not reached PLAYING in 4 s the engine calls `onReveal(true)` → `state.reveal`, which uncovers the player (blocked autoplay on phones, or a long ad). `muteAds` cannot skip or block anything (cross-origin iframe): `engines/youtube.js` mutes while the player is "quiet" (playback wanted and state UNSTARTED `-1`, or `getVideoData().video_id` differs from the track), withholds `onTime`/`onDuration`/`onEnded` during it, and after 1.5 s reports `onAd(true)` → `state.ad`, which shows `#ad-hint` with `#ad-show` ("Show player", sets `reveal`). Those two signals are guesses that have never been checked against live YouTube ads; only the fake player in `tests/links.spec.js` exercises them. The Spotify embed has no volume API and no ended event; `engines/spotify.js` derives play/pause from `playback_update` and treats "position reached duration, then silence for 1.2 s" as the end (verified live: the embed neither pauses nor rewinds). Spotify albums, playlists, shows and artists are one row each (`track.kind`, `urlTracks.isCollection`); the embed plays through the items itself, the engine reports each item's URI via `onItem` into `state.item`, and `ui.js` resolves its title through oEmbed for the Now Playing heading. The cover slot must stay at least 280 px wide.
- `js/ui.js` — the only module that touches the DOM. One `render(state)` subscriber diffs against `last` to avoid re-rendering the list on every `timeupdate`. Owns the two `<dialog>`s (`#link-dialog`, `#upload-dialog`), paste-to-add, drag-and-drop, theme (`localStorage` key `music-player:theme`, separate from settings), keyboard shortcuts (disabled while a dialog is open). It is also where the playlist is mutated after startup: `addTracks()` (dedupes by id) and `removeTrack()` (deletes from the matching IndexedDB store first) both end in `playlist.setTracks`, which keeps the current track by id. It reads `audit.isEnabled/visitorId/config` for the Privacy panel and the first-visit usage notice; the notice is hidden when `config.json` has `audit.notice: false` (currently set) or once dismissed (`music-player:audit-notice`), and the footer `#privacy-link` is hidden when it has `audit.privacyLink: false` (also currently set, so the live site shows no in-page disclosure of the log).
- `js/url-tracks.js` — `parse()` classifies a pasted URL (pure, unit-tested; returns a parsed link or `{ error: "empty"|"invalid"|"unsupported"|"playlist" }`, where SoundCloud sets are `playlist` and any unrecognised host is treated as a direct media link), `describe()` fetches oEmbed metadata (provider endpoint, then noembed.com fallback) or probes direct links, `save/loadAll/remove` persist records in IndexedDB store `url-tracks`. Cloudinary uploads are stored here too (`provider: "cloudinary"`).
- `js/cloud-upload.js` — unsigned Cloudinary upload via XHR (for progress), `validate()` (any audio or video file via `isMediaFile` from `local-files.js`, the `maxBytes` limit, and an optional `allowedFormats` extension list that `config.json` currently omits), `uploadTrack()` refuses a video whose upload response reports no audio stream (`hasNoAudio`; the check has only been exercised against stubbed responses), `toRecord()` maps the response to a URL track (`<public_id>.mp3` delivery URL, `fl_waveform` cover), `loadShared()` reads the tag-based resource list.
- `js/local-files.js` — device-only fallback: Blobs in IndexedDB store `local-tracks`. `js/db.js` owns the database (`music-player`, version 2, both stores). `js/probe.js` reads a duration with a throwaway `<audio>`.
- `js/audit.js` — usage audit log (plan.md Part D). A state subscriber only: nothing calls it to report events, and it does no DOM work. Pure `diff(prev, next)` turns two snapshots `{ids, currentId, playing, failed, item}` into events (`track_add/remove`, `play_start/end`, `play_error`, `collection_item`) and `describe(track)` maps a track to logged fields; both are unit-tested. The subscriber adds wall-clock listening time and batches to `config.audit.endpoint` as `text/plain` (no CORS preflight), with a `sendBeacon` on `pagehide`. A flush happens every `audit.flushSeconds` (15), as soon as 20 events are queued, and when the tab is hidden. Batches that fail on the network, a 5xx or a 429 persist in `localStorage` (`music-player:audit-queue`, capped at 200 events) and are retried; any other response, including the collector's 403 for a disallowed origin, counts as delivered and the events are dropped silently. `music-player:visitor` is the visitor id. `session_start` carries a library snapshot of the personal tracks already in the browser (at most 150 tracks or 40 KB, measured in UTF-8 bytes because titles are often non-Latin), which the collector adds to the catalogue without counting them as adds. With no endpoint it is inert: no visitor id, no storage, no request. `local-files.js` and `cloud-upload.js` attach a non-persisted `file: {name, bytes, mime}` to new tracks purely for this log.
- `js/media-session.js` — OS media keys / lock-screen metadata. `js/storage.js` — `localStorage` wrapper that prefixes keys with `music-player:` and swallows storage errors.

Track shape: `{ id, title, artist, src, cover, duration, source: "repo"|"local"|"url"|"shared", provider?: "direct"|"youtube"|"soundcloud"|"vimeo"|"spotify"|"cloudinary", externalId?, kind? (Spotify: track/episode/album/playlist/show/artist), hash? (Vimeo unlisted), added? }`. Ids are deterministic for URL tracks (`url-<provider>-<id|hash>`, `url-spotify-<kind>-<id>` for Spotify collections, `cloud-<public_id>`), which is how duplicates are prevented. Shared-list tracks get `shared-<public_id>`; the same upload therefore has two possible ids, and `app.js` drops the shared copy by matching `externalId` against the user's own records.

Adding a link provider touches several files: a host branch and an oEmbed endpoint in `url-tracks.js` (plus `PROVIDER_NAMES` for the badge and `SUPPORTED_TEXT`), an engine in `js/engines/` registered in the `factories` map in `player.js`, `EMBEDDED` in `ui.js` if its player must stay visible, and the provider lists in the `index.html` copy and `README.md`.

### Track list pipeline

`data/tracks.json` is generated, not hand-edited. `scripts/generate-tracks.mjs` scans `assets/audio/` (`.mp3 .ogg .m4a .wav`), derives `id` by slugifying the filename (so renaming a file changes its id and invalidates the saved `last` track), reads tags with `music-metadata`, writes embedded cover art to `assets/covers/`, and falls back to the title/artist already in the existing `tracks.json` for untagged files. `.github/workflows/generate-tracks.yml` runs it on pushes touching `assets/audio/**` and commits with `[skip ci]`. The two demo tracks are uncompressed WAV, about 74 MB in Git; don't add more large audio to the repo (`technical.md` §4).

### Audit collector (`collector/`)

A separate Cloudflare Worker + D1 deployment with its own `package.json` (wrangler); the site never imports it. `src/index.js` may only export the Worker handlers (workerd rejects any other export from the entry module), so validation, the User-Agent matcher and CSV live in `src/lib.js`, which `tests/unit/collector.test.js` imports. `POST /v1/events` checks `Origin` against `ALLOWED_ORIGINS` in `wrangler.toml` (the GitHub Pages origin and `http://localhost:8000`, so a dev server on another port is refused with 403), inserts events with `INSERT OR IGNORE` on `UNIQUE (session_id, seq)`, and only updates session device details and catalogue counters for events that were actually inserted (read back with `RETURNING`), which is what makes client retries safe. Rows are passed as one JSON parameter and expanded with `json_each`, so a request costs about five queries whatever its size; keep it that way, because D1 caps queries per Worker invocation. `/v1/admin/*` data routes need the `ADMIN_TOKEN` Worker secret: the raw tables (`sessions`, `events`, `tracks`) and the `report/*` views are all entries in one `QUERIES` table in `index.js`. `GET /v1/admin/` serves `src/admin-page.js`, a static page with no data in it that asks for the token and reads those routes; it must keep writing cells with `textContent`, since everything in the log is visitor-supplied. Adding a field to an event means adding it to both `audit.js` and the `SHAPES` whitelist in `lib.js`, otherwise the collector silently drops it. The batch limits are coupled the same way: `audit.js` sends at most 50 events or about 48 kB per request because `lib.js` rejects more than 50 events or 64 KB. Ingest is rate-limited to 60 requests a minute per IP, and a daily cron (`scheduled` handler) purges by `RETENTION_DAYS` in `wrangler.toml`; `audit.retentionDays` in `config.json` is only the number shown in the Privacy panel, so change both together. Deploy steps and saved queries are in `collector/README.md`. It is deployed as `mixtape-audit` at `https://mixtape-audit.mixtape-audit-collector.workers.dev` (the `audit.endpoint` in `config.json`), so `npm run serve` on port 8000 writes to the live log; blank the endpoint locally to avoid that.

### YouTube resolver (`resolver/`)

A separate, dependency-free Node server (`npm start` in `resolver/`, `127.0.0.1:8790`) that the site never imports. `GET /v1/audio?id=<video id>` shells out to `yt-dlp` for the audio-only stream URL and proxies the bytes with `Range` passed through. When `config.json` has `playback.resolver` (a base URL; the working copy points it at `http://127.0.0.1:8790` for local use, and committing that line makes every visitor's browser try its own localhost before falling back to the embed, so leave it out of commits unless the owner asks), `player.js` routes YouTube tracks to the `html-audio` engine with that URL as `src` and sets `state.resolved`, which makes `ui.js` clear `data-embed` (no embed, so no video and no ads). If the audio element errors, `fail()` in `player.js` adds the track to `unresolved` and reloads it through the embed engine instead of marking it failed; the track object itself is never mutated, so the audit log still records the YouTube URL. `src/server.mjs` exports `createHandler({ resolve, allowedOrigins, maxStreams })` so `tests/unit/resolver.test.js` can inject a fake lookup; the real path was checked by hand on 2026-11-17 with yt-dlp 2026.10.26 (installed with winget, which also adds Deno and ffmpeg): several videos played and seeked in Edge with no embed loaded. A first play takes 10 to 15 s, because `yt-dlp` needs about 5 s and YouTube answers 403 on a new stream URL until its `available_at` time about 5 s later; the server waits for that moment and retries a 403 twice before looking the video up again. Playwright's bundled Chromium cannot decode the AAC stream, so a real-audio check needs `channel: "msedge"`. Stream extraction is prohibited by YouTube's terms: it is meant for private use, and pointing the public site at it was recommended against (`plan.md`, third plan, §3.3; `resolver/README.md`).

### Cloudinary

`config.json` is public and safe to commit: cloud name `tivkdskh`, unsigned preset `mixtape-unsigned`. Never add an API key or secret anywhere in this repo (the collector's admin token is set with `wrangler secret put`); server-side work (signed uploads, deletes, the resolver in `plan.md` §17) belongs in a separate function with its own env. Audio uploads use `resource_type: video`. Setting `cloudName` to `""` disables cloud upload and falls back to device-only storage.

The shared playlist is whatever Cloudinary's public resource list returns for the `sharedTag` (`mixtape-public`). `allowUploaderShare` is `false`, so the "share" checkbox in the upload dialog (`#upload-shared-wrap`) stays hidden and visitors' uploads are never tagged; a track only becomes shared when the owner tags it in the Cloudinary console. `loadShared()` returns `[]` on any failure, including the 401 Cloudinary sends when "Resource list" is not enabled, so a missing shared list is silent rather than an error.

## Testing notes

Browser tests must never hit the network: they stub `config.json` (`{}` disables cloud upload and auditing; `tests/audit.spec.js` enables auditing against a routed fake endpoint and asserts on the posted bodies), `api.cloudinary.com`, `res.cloudinary.com`, oEmbed endpoints, inject a fake `window.YT` via `addInitScript`, and serve a fake Spotify iFrame API by routing its script URL to inline JavaScript. `tests/fixtures/tone.wav` is a generated 2-second 440 Hz tone used as both a direct link and an upload. The smoke test derives the expected playlist length from `data/tracks.json`, so adding repo tracks does not break it.

The unit tests import `js/audit.js`, `js/url-tracks.js` and `js/cloud-upload.js` straight into Node (and through them `state.js`, `storage.js`, `db.js`, `probe.js`), so those modules must not touch `document`, `window`, `navigator`, `localStorage` or `indexedDB` at import time, only inside functions.

Tests locate UI by element ids and ARIA state rather than text: `#play` (`aria-label` Play/Pause), `#tracks li` (`aria-current`), `#shuffle` (`aria-pressed`), `#repeat` (`data-mode`), `#cover` (`data-embed`, `data-audio-only`), `#vol-hint`, `#preview-hint`, `#ad-hint`, `#ad-show`, `.badge`, `.rm`, the `#link-*` / `#upload-*` / `.u-*` dialog controls, and `#audit-notice`, `#audit-notice-ok`, `#audit-notice-more`, `#privacy-link`, `#privacy-audit`, `#privacy-visitor`, `#privacy-close`. Renaming any of these in `index.html` or `ui.js` breaks the suite. A smoke test checks a 320 px viewport: no horizontal scroll, `#cover` at least 280 px wide, header button labels collapsed to icons.
